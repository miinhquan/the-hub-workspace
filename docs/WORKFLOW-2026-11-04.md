# Control Center rules · 4 November 2026

## Pending sales and confirmed log

Official WhatsApp incoming messages create or attach to a pending Inquiry (not a paid sale or confirmed booking). Phone contact identifiers link messages to existing inquiries. This only runs once the official webhook is configured and reachable; no live account onboarding has been performed.

The pending card shows customer, tour, departure, passengers, operator and confirmation/note. BOOKED requires staff-recorded operator confirmation and creates the confirmed Booking Log record atomically, with the available fields; staff can complete price/payment fields later. NO SLOT records the supplier outcome in Inquiry activity, keeps the customer inquiry available for another supplier, and creates no confirmed sale/booking. Cancel closes the pending inquiry, preserving its history. Older legacy pending booking records are retained but excluded from the confirmed Booking Log view.

## Inactivity and Restore

48 hours, soft archive only. Eligible active inquiries including Waiting Customer are archived. Viewing, dashboard polling, marking a notification read, reminders and background system updates do not restart the clock. An actual customer message linked through the official webhook, staff response/quotation recorded as a processing note, a substantive inquiry edit or supplier outcome resets it. Saving identical data/status does not reset it.

Waiting Operator, Booking Requested, pending/booked supplier requests, converted inquiries and all Bookings are protected. Restore returns the old active status, clears archive metadata, restarts 48h and writes an Activity Log event. Archived inquiries remain searchable. Converted history is retained. No Slot does not delete a customer request.

The scheduled Worker handler is present in source, and deploy/wrangler.example.jsonc includes a five-minute cron for the user's Cloudflare deployment. Native private Sites currently runs the same archive logic on access; background execution on that hosting is still not configured. Do not claim the native Site archives while closed. No cron or external infrastructure was changed in this UI revision.

## Monthly operating cash flow

Manual sales and actual booking payments/refunds are the income source. POS stays independent and is not included until a separate, verified consolidation process exists. Agent/operator costs and operator settlement entries are excluded; do not derive profit from this report.

A monthly review must include explicit Electricity and Water amounts (zero is accepted) and a staff confirmation that all other operating costs have been entered. Changes to operating expenses after review invalidate export. The export endpoint rechecks current server data and returns missing requirements with HTTP 409; the client button alone is not the guard. Expense stays clickable/red so missing amounts can be entered. Export is disabled/red until ready, green afterward. Currency-specific files never sum VND with USD.

Analytics shows actual recorded net receipts by creation timestamp in rolling one-hour, one-day or one-week buckets, labelled in Hanoi time. Cash + Online less Refunds; this is not profit. Amounts are plain numeric values without grouping commas.

## Authentication

The user requested no login, believing the subdomain is secret. Header identity text is removed as requested. Access remains owner-private pending informed confirmation that removing login allows anyone with the URL to read/change customer and financial records. No account or audience permissions changed in this revision.
